# exec：同步、轮询与完成通知

2026-09-13 至 14 日的本机 Codex 会话提出了三种长命令体验。这是对当时使用方式的比较，不是各产品所有版本的固定能力：

| 模式 | 模型和人的体验 |
| --- | --- |
| 同步 | 工具等命令退出才返回；期间模型不能处理别的事。命令可以向 UI 流式输出，但这不等于异步。 |
| 异步 × 轮询 | 工具先返回任务句柄；模型要反复查询状态，等待期间往往还要持续输出或安排下一次查询。 |
| 异步 × 完成后续回合 | 工具先返回任务句柄；模型可做其他事，也可结束当前回合。命令结束后由 harness 投递结果并唤醒模型，通常无需轮询。 |

选择第三种体验，同时保留短命令同步返回。这里的“回调”是 harness 收到进程完成事件后安排**后续模型回合**，不是模型注册任意代码回调。模型停止输出不等于任务完成；只要后台命令仍属当前会话，宿主就不能因当前模型回合结束而直接丢弃它。

```text
启动命令 → 短命令直接返回 / 长命令返回任务 ID → 模型继续工作或结束本回合
                                                     ↓
                           命令退出 → 完成通知 → 后续模型回合检查结果
```

## 当前 Pi 实现

Pi 0.85.1 的原生 `bash` 等进程退出才返回；stdout/stderr 流式显示不改变这一点。现有私有 Nix 配置中的 `pi-exec` 扩展覆盖了 `bash`：十秒内完成的命令直接返回，超过十秒则返回任务 ID；`background: true` 可立即后台化。完成结果通过 `followUp` 消息触发后续模型回合，不要求模型轮询。`exec_status` 用于人工查看进度或排障，`exec_cancel` 用于取消；`timeout` 是秒数形式的**硬截止**，不是十秒自动后台化的等待间隔。

交互式/RPC 会话可在后台任务完成后续跑；`print/json` 模式则需在退出前等待当前会话的后台命令，并消费完成通知。实际关闭或切换会话时应清理进程树。该扩展只管理单次会话内的执行，不负责跨会话恢复、长期工单或 Agent 身份；这些仍属于上层平台。

完成通知目前没有持久化的消费确认与重试协议，不能仅凭命令退出码为零或 Pi 进程退出码为零断言结果已交付。长命令的完整输出保存在受限磁盘日志中，给模型的默认结果只保留有界尾部。实现、试用范围及验收细节见 [Pi harness 调查与试用记录](research.md)。

模型响应本身达到输出上限或被用户中断时，历史回合如何重放是另一层问题；Pi、OpenCode、DeepSeek Harness 和 Codex 的对照实测见 [截断与中断回合的重放](turn-replay.md)。
